# 深圳大学校园网自动认证：常见问题与排障

本页适用于 Windows 上的深圳大学（SZU）校园网、SRun、`SZU_WLAN` 和教学区网络自动认证问题。

## Wi-Fi 显示已连接，但网页打不开

这通常是校园网认证失效，常见于同一账号在另一台设备登录后被顶下线。保持 Wi-Fi 已连接，等待下一次检测，或从托盘菜单选择“立即检查”。程序会在首次 Ping 失败后发起一次认证，而不是连续反复提交登录请求。

若 Windows Wi-Fi 面板中的“认证”能打开浏览器门户页，说明无线连接仍在；此时不需要手动断开 Wi-Fi。请让程序使用当前网络重新发现门户参数。

## 显示“未发现当前网络的认证门户”

确认已连接深圳大学校园网，并尝试在浏览器中打开任意 HTTP 页面以确认系统可以出现认证页面。某些代理、VPN 或 TUN 会接管网络探测，导致常规 HTTP 302 检测无法看见真实门户。

v1.0.4 及更新版本会尝试通过活动的物理 WLAN/以太网网卡直接查询 `net.szu.edu.cn`，避开 `198.18.0.0/15` Fake-IP。请先升级到最新 Release；若仍失败，请附上脱敏日志和网络名称提交 Issue。

## 显示“无法通过校园网物理网卡连接认证服务器”

关闭或暂时暂停会改写 DNS/路由的代理、VPN、游戏加速器或 TUN 软件后重试。程序不会关闭 TLS 证书校验，也不会秘密回退到某个教学区 IP，因此这个提示意味着当前物理网卡无法到达动态发现的门户。

## 为什么程序不会每几秒重试一次？

为避免多个进程、多个计时器或短暂丢包导致重复认证，程序每轮检查相隔至少 60 秒；认证失败后也有至少 60 秒冷却。每个 Windows 用户只能运行一个实例，日志包含 PID 以便排查重复进程。

## 如何安全地反馈日志？

从托盘菜单打开日志，只复制与故障时间相邻的几行。提交前确认日志中没有账号、密码、MAC、完整私有 IP，以及门户 URL 中的 `uaddress`、`umac`。请说明应用版本、Windows 版本、SSID 和托盘显示的可读错误。

## 仍无法解决？

请在 [GitHub Issues](https://github.com/charles-webber/szu-network-monitor/issues) 创建反馈，并按 [贡献指南](../CONTRIBUTING.md) 提供已脱敏的复现信息。不同校区、SSID 和网络软件组合的报告尤其有价值。
